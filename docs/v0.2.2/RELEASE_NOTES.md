# v0.2.2 Release Notes

发布日期：2026-09-13
版本状态：**已部署，待人工验收**
版本定位：电子阅读器保护壳前台体验与机型内容体系升级

> v0.2.2 已完成蓝绿发布与线上技术验收。登录与支付导航回归、Google 结构化数据验证完成后，将状态更新为“已验收关闭”。

## 版本亮点

- 首页围绕“量卷裁衣”重新设计，新增品牌与机型两级选择、别名搜索、已开模商品、新开模内容、意向登记和五步交付流程。
- 新增电子阅读器机型库，首批支持阅星瞳、Kindle、掌阅和文石/BOOX 四个品牌及各一个代表机型。
- 新增机型落地页，展示年份、停产状态、外形尺寸、接口位置、兼容机型、关联商品及开模意向登记。
- 新增后台机型管理，支持品牌、机型及商品关联维护，并接入权限控制和操作审计。
- 完成首页、商品和机型页面的 SEO、结构化数据、图片加载、可访问性与性能治理。

## 前台体验

- 首页设备选择器支持品牌、型号和 aliases 搜索，可通过方向键、Enter 和 Escape 完成操作。
- 首页、商品列表、分类列表、商品详情和机型页补齐加载、错误、空数据及未找到状态。
- 全站统一 focus-visible 和减少动画偏好，主要页面在 360、390、768、1440 四档视口下无横向滚动。
- 首页、机型页、商品页和结算页统一使用“7 天内发出”的交付口径，并明确为自然日。
- 商城与后台站内导航迁移到 Next.js Router；支付宝外部支付跳转继续使用浏览器级导航。
- 公共导航、交易状态、错误提示、交付、运费、售后和品牌 SEO 文案集中到中文语言模块。

## 机型库与意向登记

- 新增 device_brands、device_models、product_device_models 和 model_requests 四张表。
- 支持品牌/型号别名、停产状态、开模状态、尺寸、兼容组及商品多对多关联。
- 新增 device:manage 权限，机型后台写操作与 admin_operation_logs 审计记录保持同事务。
- 意向登记统一邮箱小写化，支持重复登记提示、并发唯一性保护、同 IP 频率限制和人数统计。
- 本期只负责收集开模意向；开模完成后的邮件通知能力计划在 v0.3.1 提供。
- 新表启用 RLS，撤销 anon 和 authenticated 的直接 DML 权限，仅由受控服务端访问。

## SEO 与内容

- 首页标题、描述和正文聚焦“电子阅读器保护壳”及主要设备品牌。
- 新增按机型组织的动态 sitemap；robots 屏蔽后台、账户、结算和 API 路径。
- 首页提供 Organization、WebSite 和 ItemList。
- 商品详情提供 Product、Offer 和 BreadcrumbList。
- 机型页提供 BreadcrumbList，以及存在关联商品时的 ItemList。
- canonical、sitemap 和 JSON-LD 均基于 NEXT_PUBLIC_SITE_URL，不硬编码本地地址或服务器 IP。
- JSON-LD 保留小于号转义与恶意文本测试，避免结束 script 标签注入。

## 性能优化

- 首页 banner、站点信息、分类、商品和机型数据使用带标签的服务端缓存。
- 商品、分类、耗材、站点及机型后台发生变更后会失效对应缓存。
- 生产模式连续访问验证：首次请求读取机型与品牌数据，第二次请求命中缓存且未重复查库。
- 首页内容图片迁移到 next/image，Supabase Storage 公共域名已纳入图片优化配置。
- 3D Viewer 保持按需加载，不进入首屏 JavaScript。
- 本地移动端 Lighthouse 基线：Performance 97、Accessibility 100、SEO 100、LCP 2,119 ms、CLS 0。

## 稳定性修复

- 修复 Drizzle 将 PostgreSQL 唯一约束错误包装在 cause 中时，意向重复登记误返回 500 的问题。
- 修复设备搜索结果只能点击、无法通过键盘激活的问题。
- 调整计价测试夹具的生效时间，避免数据库与应用主机轻微时钟偏差导致偶发失败；业务计价规则未改变。
- 商品名称校验拒绝“官方”“原装”“授权”等可能造成第三方品牌误导的表述。

## 数据库升级

升级目标环境前先确认数据库与恢复点，然后执行：

~~~bash
pnpm db:migrate
~~~

本版本新增迁移：

- 0003_handy_monster_badoon.sql
- 仅新增机型与意向登记相关表，不修改订单、库存、支付、退款或生产链路表。

机型种子脚本默认为预览模式，确认目标环境后按脚本提示显式执行写入。脚本可重复执行，并保持数据幂等。

## 部署后外部核查发现（2026-09-12）

以下两项由外部线上抓取核实，不阻塞版本关闭，但需尽快处理。

### 1. ⚠️ 商品数据仍是旧定位残留

`sitemap.xml` 共 8 条，其中唯一的商品是 `/products/geometric-ambient-lamp`（几何氛围灯），分类为 `desktop-home`；四个机型页全部显示「暂无现成保护壳，0 人已登记」。

结果是：站点通篇介绍自己专做电子阅读器保护壳，**而唯一可购买的商品是一盏氛围灯**。访客点击「现在就能买的」会得到与站点主张无关的结果；机型长尾词即便起量，流量也落不到任何可售商品上。

这不是代码缺陷，是**商品数据没跟上 2026-09-10 的定位变更**（见 `OPEN-DECISIONS.md` A26）。两条处理路径：

- 尽快上架第一批保护壳商品（依赖实物设备与开模进度）；
- 或先下架氛围灯，让首页诚实显示「正在准备第一批」——**空着比答非所问好**。

### 2. ⚠️ 机型页 H1 疑似为品牌名

抓取 `/devices/xteink/x4-classic-v2` 得到的 H1 是「书衣」。若属实，与 `BRAND-COPY.md` 7.3 的模板 `{品牌}{型号} 保护壳｜书衣` 不符。

**H1 是长尾 SEO 权重最高的位置**，用品牌名会浪费掉「阅星瞳 X4 Classic 保护壳」这个核心关键词——而机型长尾词正是本版本 SEO 策略的全部依据。

需在浏览器中确认实际 `<h1>` 元素内容（抓取工具可能把页头 logo 误判为 H1）。若确为品牌名，应修正为「机型 + 品类」。
