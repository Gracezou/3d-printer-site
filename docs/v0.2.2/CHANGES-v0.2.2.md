## 0. 定位变更与版本边界调整

### 0.1 定位变更

本版本起，产品定位由「3D 打印摆件 / 家居 / 氛围灯」变更为：

> **专做电子阅读器保护壳的按单打印店。** 覆盖阅星瞳、Kindle、掌阅、文石等品牌，也做停产老机型。开模顺序由需求量决定。

完整表述与理由见 `docs/OPEN-DECISIONS.md` A26。上一版 `CHANGES-v0.2.2.md` 中所有基于旧品类的文案与 SEO 关键词**全部作废**。

### 0.2 版本边界调整（重要）

上一版声明「无数据模型变更」。**本版本必须放弃这条边界**，理由：

新定位下，首页的核心是**设备选择器**，站内 SEO 主力是**机型落地页**，需求收集靠**意向登记**——三者全部依赖机型数据。没有机型库，首页只能做一半，SEO 无从谈起。为守住"零改表"而把首页做两遍，代价远大于收益。

新边界：**新增机型库与意向登记相关的表，不触碰订单、库存、支付、退款任何一张表。**

### 3.3 首页重构（按新定位）

> 用户是**带着确定目标来的**——他有一台什么机器，就要那台机器的壳。首页第一屏的核心是设备选择器，不是商品网格。

#### T120 首页数据缓存重构
- 依赖：无
- `getHomePageData` 依赖的数据从 React `cache()` 迁移到 `unstable_cache` + tag，比照 `getStorefrontSiteInfo`
- 保留 `dynamic = 'force-dynamic'`，构建期不需要数据库凭据
- 后台变更商品、机型、站点信息时调用 `revalidateTag`
- **验收**：连续访问首页不再产生重复数据库查询；后台变更后一次刷新内反映

#### T121 精选与最新上架去重
- 依赖：无
- 服务端从「最新」中排除已出现在「精选」的商品
- 数量不足时**宁可某组为空并展示占位，也不重复展示同一商品**
- **验收**：首页任一商品最多出现一次

#### T122 Hero 与设备选择器
- 依赖：T140、T150、品牌文案（[`BRAND-COPY.md`](./BRAND-COPY.md) 已定稿）
- Hero = 固定文案层（H1 + 副标题）+ **设备选择器**
- 设备选择器：品牌 → 型号两级选择，并提供型号搜索框（支持别名匹配）
- 文案来自语言包（已决 A11）
- 目标：**用户三秒内可到达自己的机型页**

**⚠️ H1 意象化与 SEO 的取舍（已决 A32）**

H1 定为「量卷裁衣」，**不含任何品类关键词**。这是一次有意识的取舍——保住 H1 的美感，把关键词补在别处。因此以下四处**必须**含核心品类词，缺一不可：

1. H1 紧邻的副标题——须含「电子阅读器」与「壳」
2. 首页 `title`——须含「电子阅读器保护壳」（T128）
3. 首页 `description`——须含品类词与主要品牌名（T128）
4. 首页 SEO 正文首段——即出现「电子阅读器保护壳」（T125）

**⚠️ 留白不得挤走设备选择器**

主标题走意象、版式偏留白时，容易把首屏做成只剩一句话和一张图。但首屏的核心指标是**三秒到达机型页**——设备选择器必须与 H1 处于同一屏，不得被推到折叠线以下。留白用于给选择器呼吸感，不是把它挤走。

- **验收**：
  1. banner 为空或加载失败时，第一屏仍有完整 H1、副标题与可用的设备选择器
  2. 四档视口（360 / 390 / 768 / 1440）下设备选择器均在首屏可见，无需滚动
  3. 上述四处关键词补偿全部落实

### 3.4 机型落地页与 SEO

> **机型页是本站 SEO 的主力。**「阅星瞳 X4 保护壳」这类长尾词竞争极低、购买意图极强。

#### T154 机型落地页
- 依赖：T150、T152、T141
- 路由：`/devices/[brand]/[model]`

**不触碰** orders / order_items / payments / refunds / print_jobs / materials / product_variants 任何一张表。

### 4.1 `device_brands`（新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid PK | |
| `name` | varchar(50) | 品牌名，如「阅星瞳」 |
| `slug` | varchar(50) unique | URL 片段 |
| `aliases` | jsonb | 别名，如 `["XTEINK","阅星曈"]` |
| `sort_order` | int | |
| `is_visible` | boolean | |

### 4.2 `device_models`（新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid PK | |
| `brand_id` | uuid FK → device_brands | |
| `name` | varchar(80) | 型号名，如「X4」 |
| `slug` | varchar(80) | 品牌内唯一 |

| `dimensions` | jsonb | 长宽厚等外形尺寸 |

| `notes` | text | 接口位置等补充说明 |
| `is_visible` | boolean | |

约束：`unique(brand_id, slug)`；索引 `idx_device_models_brand`。

### 4.3 `product_device_models`（新增，多对多）

| 字段 | 类型 |
|---|---|
| `product_id` | uuid FK → products |
| `device_model_id` | uuid FK → device_models |

主键 `(product_id, device_model_id)`。

### 4.4 `model_requests`（新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid PK | |
| `device_model_id` | uuid FK → device_models | |
| `email` | varchar(255) | |
| `note` | varchar(200) | 用户补充说明 |
| `status` | varchar(20) | `pending` / `notified` / `fulfilled` |

### 4.5 迁移要求

- 迁移必须**前向兼容**，发布前建立 Supabase 可恢复点
- 新表外键仅指向 `products` 与自身，不引入建表顺序前向依赖

## 5. 接口变更

| 方法与路径 | 说明 |
|---|---|
| `GET /api/devices` | 品牌与机型列表，供设备选择器使用 |
| `GET /api/devices/[brand]/[model]` | 机型详情与该机型可买商品 |
| `GET /api/devices/search?q=` | 机型搜索，**须匹配别名** |
| `POST /api/model-requests` | 提交意向登记（含频率限制） |
| `GET /api/admin/devices` 等 | 后台机型管理，需 `device:manage` |

新增错误码（现有已用到 40912）：

| 码 | 常量 | HTTP | 场景 |
|---|---|---|---|
| 40913 | `MODEL_REQUEST_EXISTS` | 409 | 同一邮箱已登记该机型 |
| 40914 | `MODEL_REQUEST_RATE_LIMITED` | 429 | 登记频率超限 |

> ⚠️ v0.3.0 的退款相关错误码需相应顺延至 40915 起，届时同步修订 `CHANGES-v0.3.0.md`。

## 7. 遗留风险

| 项 | 说明 |
|---|---|
| **thin content 牵连整站权重** | 大批空机型页可能被判定为 doorway page。T154 的内容质量验收必须从严，宁可少上机型也不要上空壳页面 |
| 机型数据准确性 | 尺寸、接口位置录错会直接导致壳装不上。**建议只录入有实物或可靠资料的机型** |
| **外壳品类的退货率高于摆件** | 保护壳是精密配合件，"装不上""卡扣松""开孔偏"的投诉率显著更高。这会冲击 v0.3.0 已定的退款规则（A10：开始打印后不允许客户申请退款），需在 v0.3.0 增加尺寸不符的例外情形 |
| 耗材选型 | PLA 做外壳偏脆且夏季易变形，PETG / TPU 更合适。这会影响 BOM 与商品页参数展示，需在上架前确认 |
| 交期承诺口径 | 已定稿为 **7 天（自然日）+ 逐单装机复核**。二者都是硬承诺，产能不足时会直接转化为客诉与退款请求。旺季前需评估产能是否仍能兑现 |
| **品牌商标已被他人注册** | 「书衣」检索完成，商标已被占用，**经评估后决定沿用（已接受风险，见 `OPEN-DECISIONS.md` A37 与 §I）**。注意本版本的 SEO 投入与该风险方向相反——机型长尾词做起来的过程，同时也在提高被权利人发现的概率。触发条件与备选名见 §I |
| 导航改造回归面 | T142 触及 31 处跳转，含登录回跳与支付外跳，支付相关必须单独回归 |
| 设计 Token 收敛不彻底 | 会导致 v0.2.3 的页面继续各写各的，T140 验收从严 |
| 意向登记无通知能力 | 本期只登记不通知，用户体验不完整。开模通知归 v0.3.1，需在页面文案中说明"做出来后会通知你"并确保 v0.3.1 兑现 |
| 域名变更 | 当前 `printer.daxiaoxiang.com`。若更换，canonical、sitemap 与结构化数据须随 `NEXT_PUBLIC_SITE_URL` 变化 |
