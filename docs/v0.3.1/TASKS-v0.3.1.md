## B0 · 合并版基线

### T216 现状与契约

- [x] 记录 v0.3.0 用户路径的代码基线与 Stage 只读 HTTP 基线；浏览器截图及同条件视觉性能对比随 B2/B3 设计讨论进行。见 [B0/B1 基线与邮件契约](./B0-B1-BASELINE-AND-EMAIL.md)。
- [x] 固定邮件事件矩阵（触发状态、收件人、模板、链接、去重键），明确支付/退款重复回调和状态回退的处理规则。
- [x] 业务邮件采用独立 SMTP 配置及 `notify.` 身份；Stage 使用受控邮箱白名单；提供失败观察/重排脚本，不复用 Supabase 登录 OTP 模板。
- [x] 设计 0009 前向兼容迁移与回滚；在隔离 PostgreSQL 17 完成迁移与权限验证。Stage/生产库身份将在发布前由既有脚本再次核对。

## B1 · 通知能力（原 v0.3.1）

### T217 业务邮件基础设施

- [x] 建立业务邮件队列、唯一去重键、模板类型和安全的重试/失败状态；事务内仅入队，定时任务批量发送并防止并发重复认领。
- [x] 配置独立 SMTP 适配、发件域与环境变量模板；日志遮蔽收件人及凭据，不在任务失败日志泄露邮件正文中的个人信息。
- [x] 使用隔离数据库和假邮件提供方验证发送成功、超时/未知、重试、重放与坏消息隔离；未知投递结果转人工核实，不盲目重发；邮件故障不回滚订单事务。

### T218 订单与售后邮件

- [x] 支付成功、开始生产、发货、审核通过/驳回及退款成功按事件矩阵入队；只发给订单所有者。
- [x] 邮件状态、订单编号、链接与站内真实状态一致；重放回调或重复执行 Cron 不能重复入队/认领，取消/失败不能误发成功邮件。
- [x] 更新售后页「本期不发送邮件」等过期说明，并保留站内查询入口。

### T219 意向登记开模通知

- [x] 仅机型已开模且存在可见、在售、有可售库存的关联商品时，向该机型待通知登记邮箱入队；无可购商品或仅勾选已开模时不发。
- [x] 同一登记/开模事件幂等；明确失败可重试、未知结果转人工，成功后更新登记状态；通知链接落在真实机型页面。
- [x] 更新机型登记页「本期仅收集意向」文案；Stage 受控邮箱的真实投递验收并入 T226。

## B2 · 商品发现与展示（原 v0.3.2 + 本次四项）

### T220 机型适配与筛选

- [ ] 首页机型选择更早可见；列表移动筛选及条件展示清晰，刷新/前进后退不丢条件，也不发生整页闪白。
- [ ] 机型选择上下文贯穿列表、详情、购物车和订单；所有适配声明以商品关联和机型数据为准，误配时能明确提示。
- [ ] 相近型号、兼容组与暂无商品状态有明确说明和恢复入口。

### T221 关联规格选择

- [ ] 新值与旧值冲突时清除冲突维度并提示下一项；提供重选入口，区分不存在组合与售罄组合。
- [ ] 颜色有文字名称，材质/工艺有简短说明；价格、库存、购买状态同步且无无效可购中间态。
- [ ] 从任一有效组合可换到另一有效组合；不同选取顺序均可完成购买。商品详情手机端购买入口适配安全区域。

### T222 视觉统一与可信商品信息

- [ ] 统一前台容器、按钮、输入框、间距、边框及状态 Token；减少不必要的大圆角、阴影和多层卡片，保留图片与品牌色的展示重点。
- [ ] 首页、机型页、列表、详情、购物车、结算、订单和个人中心完成一致的层级与移动端布局；不牺牲触控面积与对比度。
- [ ] 详情页展示实际拥有的实物/装机素材、适配限制、工艺、生产交期、运费和售后信息；素材不足时不以效果图冒充实拍，也不写超出实际能力的承诺。
- [ ] 交期文案与既有「7 天内发出」口径一致；内容通过语言包和代码发布维护。

## B3 · 购买完成与可用性（原 v0.3.2）

### T223 购物车、结算与账户页

- [ ] 加购、数量调整和删除即时反馈；连续请求不导致数量回跳，失败只回滚对应商品。
- [ ] 地址、优惠及运费预览局部反馈；下单防重复提交，不变更实际费用计算。支付外跳与回跳仍能完成。
- [ ] 账户以订单/售后进度和下一步操作为主，登录后恢复安全的原购买路径；站内核心购物跳转减少非必要整页加载。
- [ ] 关键页面具备加载、错误、空数据和未找到状态，并提供恢复操作。

### T224 移动端与可访问性

- [ ] 验证 360/390/768/1440px 下无横向溢出、重要按钮无遮挡，表单键盘弹出时购物操作仍可完成。
- [ ] 检查键盘操作、焦点可见、字段错误关联、异步状态播报、对话框焦点与减少动画偏好。
- [ ] 商品详情固定购买入口不遮挡内容；购物车与结算页采用页内汇总操作。
