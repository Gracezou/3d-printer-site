# 我的订单页面建议与本轮反馈

日期：2026-10-16。页面优化建议已获确认并完成本地实现、自测；未部署。前一批改动已提交为 `c8f60fd`。

## 建议方案

1. **每单只有一个强调操作**：待支付突出「去支付」，已发货突出「确认收货」，其他状态突出「查看详情」。取消放次级位置，保留确认提示，不让红色按钮抢过主操作。
2. **订单卡片按阅读顺序组织**：订单号/时间和状态 → 商品与规格/适配 → 进度说明 → 金额与操作。多商品先显示前两件，再展开全部；退款金额与实付金额分开标明。
3. **筛选与返回保留位置**：移动端状态标签横向滚动；状态和页码写入 URL，进入详情后返回原筛选和页码。售后状态独立展示，不覆盖原订单状态。
4. **反馈留在对应订单旁**：取消或确认收货只让该订单进入处理中，其他订单继续可浏览；失败在该卡片提示并提供重试，而非仅顶部报错。
5. **移动端固定卡片操作位置**：金额单独一行，按钮靠右或等宽换行，不做全页悬浮操作栏，避免误操作其他订单。支付剩余时间只在接口提供真实保留截止时间后显示，不虚构倒计时。

实施顺序：操作层级和卡片结构 → URL 状态恢复 → 逐卡片反馈 → 多商品折叠，以上均已完成。

## 订单页优化交付

- 待支付强调「去支付」、待收货强调「确认收货」、其他状态强调「查看详情」；同卡片仅一个主按钮，取消仍需确认。
- 卡片按状态、商品、进度、金额、操作展示；默认显示前两款商品，可展开全部/收起。实付金额与累计退款金额分开显示，不修改金额计算。
- 状态和页码保存到 URL；刷新、浏览器前进后退及详情页「返回订单列表」恢复筛选页码。详情页返回参数只允许订单列表及支持的筛选字段，不能用于外部跳转。
- 操作按订单独立锁定，支持不同订单并行操作；失败提示及重试留在当前卡片。取消处理中阻止该单支付跳转。已成功的动作即使后续刷新失败也不会再次展示操作按钮。
- 页码因取消订单等原因超过最新总页数时回到最后有效页；无数据回第 1 页，避免永久停留空白页。
- 移动端筛选横向滚动，金额独立一行，操作靠右换行，无全页悬浮操作条。接口已有 `reservedUntil` 时展示真实截止时间，否则不显示虚构倒计时。

## 本轮已修改

- 备案号默认值「鲁ICP备2026057815号」及工信部链接。环境变量非空时仍优先；已有 Stage/生产示例中用户填入的同号内容予以保留，未修改用户真实环境文件或远程构建配置。
- 商品基础信息与变体原本独立保存。底部按钮在基础信息有修改时明确显示「保存全部修改」，先保存基础信息再保存变体，全部成功后解除离开提醒。
- 基础信息失败时不继续写变体；变体失败时保留变体草稿及提醒，并明确基础信息是否已保存。只点「保存基础信息」时仍提醒未保存的变体，防止真实修改丢失。
- 订单按钮同时修正链接/按钮间高度和圆角差异；把覆盖字号的全局 `font: inherit` 放入 CSS base 层，让页面的字号/字重设置生效。
