# Release Notes v0.2.0

发布日期：2026-09-07  
版本定位：新加坡验证环境版本

> 本版本仅用于境外验证和支付宝沙箱联调，禁止接入真实用户或保存真实个人信息，不应作为生产环境直接上线。

## 版本亮点

- 用户登录由短信验证码调整为 Supabase 邮箱 OTP，支持 6 至 10 位验证码和自定义 SMTP。
- 新增个人资料维护，可配置昵称和下单时默认带入的联系电话。
- 收货地址支持粘贴姓名、手机号和完整地址后快捷识别。
- 商品筛选改为客户端路由更新，刷新、前进后退和分享链接后仍保留条件。
- 稀疏 SKU 支持自动切换到兼容组合，也可以再次点击取消当前规格。
- 暂时隐藏与“全部作品”重复的“本周新作”导航入口。
- 用户端页面和商品参数完成中文化治理。
- 结算页会明确展示满额包邮、优惠码包邮或实际命中的运费规则。

## 性能与交互

- 商城公共布局不再为每个页面重复读取完整首页数据，站点信息使用短时缓存。
- 商品详情和实时库存接口由多次串行数据库访问收敛为单次查询。
- 商品列表图片采用浏览器懒加载，降低首屏无关资源请求。
- 购物车数量调整采用乐观更新和 250ms 连续操作合并。
- 删除购物车商品时立即更新界面，服务端失败才恢复原状态。
- 购物车页面与顶部数量共享服务端返回结果，不再重复拉取完整购物车。
- 商品、库存和购物车接口增加 `Server-Timing`；超过 500ms 的请求记录脱敏慢请求日志。

本地开发环境访问新加坡 Supabase 的预热单次采样：

| 路径 | 优化前 | 优化后 |
|---|---:|---:|
| 商品列表接口 | 2.572s | 0.671s |
| 商品详情页 | 1.051s | 0.534s |
| 实时库存接口 | 1.904s | 0.665s |

采样仅用于验证优化方向，不代表生产环境 SLA。部署后仍需持续采集 p50/p95。

## 数据与接口变更

- 新增 `user_profiles.email` 唯一索引。
- 用户联系电话调整为可选默认联系电话，不再作为登录标识。
- `POST /api/auth/send-code` 和 `POST /api/auth/verify` 改为邮箱 OTP 参数。
- `GET/PATCH /api/auth/me` 支持邮箱、昵称和默认联系电话。
- 订单试算响应新增运费规则、包邮门槛和免邮原因。
- 购物车修改响应新增最新购物车商品总数。

升级已有环境前执行：

```bash
pnpm db:migrate
```

## 配置要求

- 本地命令统一读取 `.env.dev`，服务端口为 `5003`。
- Supabase 启用 Email Auth，并在 Magic Link or OTP 模板中使用 `{{ .Token }}`。
- 对外测试前配置自定义 SMTP，并检查发件域名、限流和投递情况。
- 运费通过“管理后台 → 系统设置 → 运费规则”维护，不通过环境变量配置。
- 支付仅使用支付宝沙箱，`ENABLE_MOCK_PAYMENT=false`。

## 验证结果

- ESLint 通过。
- TypeScript 类型检查通过。
- 35 项单元测试通过。
- Next.js 生产构建通过。
- 商品列表、商品详情、库存、购物车、订单试算、用户资料和后台运费配置功能测试通过。

## 已知问题

- 打开 Chrome DevTools 并进行客户端页面跳转时，可能出现 `et.reportAllChanges` 读取 `startTime` 失败。该异常来自 DevTools 注入的 Web Vitals 脚本，不影响正常用户页面；可关闭 DevTools 验证业务，等待 Chromium 修复后升级浏览器。
- 地址快捷识别使用本地规则，不调用地图服务，非常规地址写法仍需人工补充并核对。
- 当前为境外验证环境，Supabase 在中国大陆的网络可达性不作为生产承诺。
- 支付宝沙箱退款行为可能与生产环境不同，正式上线前必须重新验收。
