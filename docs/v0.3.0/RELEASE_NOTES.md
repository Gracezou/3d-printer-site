# v0.3.0 Release Notes

发布日期：2026-10-15
版本状态：**开发完成，待支付宝沙箱回归与部署后人工验收**
版本定位：退款引擎商品级重构 + 客户端售后申请 + 后台运营体验优化（动钱与库存的版本）

> 本文档为发布候选版本。完成 B4 支付宝沙箱真实付款与退款回归（见 [沙箱回归手册](./ALIPAY-SANDBOX-REFUND-RUNBOOK.md)）、B5 Stage 部署后真实角色人工验收，并按 [依赖安全修复记录](./DEPENDENCY-SECURITY.md) 处理 `braces` 高危依赖（Stage 受限例外 2026-11-15 UTC 到期，生产不放行）后，将状态更新为「已验收关闭」。

## 版本亮点

- 退款从订单级重构为商品级：优惠按商品小计比例分摊、运费只在全部商品退完时一并退、库存按 BOM 快照逐件返还、退款成功后按剩余件数联动打印队列。
- 修复既有缺陷：此前部分退款完全不返还库存，本期一并修复。
- 新增客户端售后申请：申请单 → 后台审核 → 退款的两段式流程；尺寸不符/装配问题例外受理；凭证图片受安全校验与频率限制保护。
- 新增后台审核队列与 `return:review` 权限码；支付宝退款结果按 success/rejected/unknown 三态处理，unknown 转人工复核，支持原退款号续记与人工核实后作废。
- 2026-10-15 追加：后台运营体验优化——统一布局密度、角色分栏权限编辑、设置分组保存、分类树与抽屉、耗材/商品录入简化、列表筛选入 URL 与未保存提醒。
- 依赖安全：定向升级可用补丁，严重漏洞归零；`braces` 高危以补丁加 Stage 受限审计例外处理，生产不放行。

## 退款引擎

- `refunds` 保留为一次退款操作的头，`amount` 由商品明细汇总；`restock` 下沉到 `refund_items`，运营审核时按件决定是否返还库存。
- 优惠按商品小计比例分摊，最后一项用「实付总额 − 已分摊之和」兜底；三件不同单价 + 满减 + 运费的订单逐件退完，累计退款额精确等于实付金额（本版本验收红线）。
- 运费规则：部分退款不退运费；全部商品退完时连运费一起退；退货后跌破包邮门槛不补收运费。
- 库存返还按 `order_items.bom_snapshot` 快照计算，不读实时 BOM；库存流水以 `refund_item` 为 `ref_id`，可逐条追溯。
- 打印队列联动：按「购买量 − 成功累计已退量」重算 `queued` 数量，减至 0 才移出队列；`printing` 及之后不自动取消（耗材已消耗，需人工判断）。
- 幂等与并发：退款幂等键限定「订单 + 键」；`(refund_id, order_item_id)` 唯一约束防重复明细；处理租约使用数据库时钟并在每次渠道调用前续租；并发发起同一商品退款只有一次成功，重放回调不产生重复流水。
- 渠道三态：`success` 正常落账；首次明确拒绝可标记 `failed`；一旦出现 `unknown` 保持 `pending + needs_manual_review`，只能使用原退款号续记，后续拒绝也不再落 `failed`。
- 订单状态：全部退完 → `refunded`；部分退款保持原状态（保留 `96126c5` 修复语义并补齐回归测试）。
- 人工核实后作废：先原子抢占处理租约，再实时查询渠道，仅 `not_found` 允许作废结案；渠道确认成功时续记落账；不确定时保持人工复核。
- 保持 Provider 抽象，不引用任何支付宝 SDK 类型或字段名；不改动支付（`payments`）与下单（`order.service.ts`）既有逻辑。

## 客户端售后申请

- 用户按商品发起申请（可多选订单内商品）；同一订单同时只允许一条 `pending` 申请（部分唯一索引）。
- 准入规则集中可配置、不硬编码；普通原因仅打印任务为 `queued` 时可申请（`printing` 起不允许），尺寸不符/装配问题为例外情形，任何状态可提交并由有权后台人员放行。
- 凭证图片复用既有上传安全校验（权限、扩展名、体积、magic number），仅接受本站 `returns/<user_id>/<年>/<月>/` 对象路径；每用户每小时最多 20 次；超过 24 小时未关联申请的孤儿文件由 cron 分页扫描清理，删除前二次确认引用关系。
- 申请单本身不动钱、不动库存，仅记录诉求；审核结果在站内订单中心查看（邮件通知归 v0.3.1，页面文案已明示）。

## 后台审核与权限

- 新增权限码 `return:review`，纳入既有 RBAC 与角色配置页；审核列表与驳回要求 `return:review`，批准要求 `return:review` + `order:refund`，直接退款、续记与作废要求 `order:refund`。
- 审核界面展示每件商品当前打印状态、已退/可退余额与异常标记，供运营判断是否返库；历史金额异常的申请仅该条可退金额显示为「—」。
- 审核动作与 `admin_operation_logs` 同事务写入；客户准入规则只在提交申请时执行，审核期间商品进入打印后管理员仍可批准，退款引擎继续在锁内校验可退数量与金额。

## 后台运营体验（2026-10-15 追加）

- 统一后台页面宽度、标题、间距、圆角与控件密度，紧凑扁平布局；移动端保留较大操作区域。
- 权限管理采用左侧角色列表、右侧分组权限编辑，支持分组计数、全选、修改已有角色前提示影响账号数量及固定保存栏。
- 系统设置按「站点与轮播图」「运费规则」分组导航并独立保存，显示未保存状态。
- 分类管理提供可折叠、可搜索的树状列表与编辑抽屉；耗材补货、盘库等高频操作外露。
- 耗材编号与名称随颜色、品牌、类型自动生成；采购批次号改为「日期 + 自定义订单号」；新商品 Slug 根据分类、名称可用字符及固定后缀生成，已有商品链接不随分类改变。
- 列表筛选、分页、分类搜索/折叠与设置分组记录到 URL，刷新保留状态；分类、耗材、账号短表单使用右侧抽屉；角色、设置、商品编辑与抽屉增加未保存提醒。
- 详见 [后台运营体验验收](./ADMIN-UX-ACCEPTANCE.md)。
