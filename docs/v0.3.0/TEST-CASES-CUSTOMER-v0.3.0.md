## 测试环境

- **地址**：stage `http://stage.printer.daxiaoxiang.com`（**HTTP，长期如此，只放测试数据**）。
- **版本**：`v0.3.0+sha-353110e…`，使用独立的 stage Supabase 数据库。
- **支付**：支付宝沙箱，`ENABLE_MOCK_PAYMENT=false`。沙箱只读自检曾报验签失败，待 Grace 实测确认；若付款或退款提示签名/验签失败，**核对填的是支付宝公钥而非应用公钥**（两者容易混淆）。
- **初始数据**：5 款阅读器保护壳（阅星瞳 X3、阅星瞳 X4 Classic、Kindle Paperwhite 11、掌阅 Ocean 4 Turbo、文石 BOOX Go 7）共 9 个规格、7 种耗材、4 品牌 5 机型、1 条运费规则、3 个折扣码、1 个超级管理员。
- **折扣码**（stage 预置，名称以后台实际为准）：
  - 满 99 减 20（`fixed_amount`，满 99 元减 20 元）；
  - 九折封顶 50（`percentage`，`discountValue=0.9`，最高减 50 元）；
  - 满 79 包邮（`free_shipping`，满 79 元免运费）。
- **后台账号**：凭据见本机 `.local/stage-admin-credentials`（只写「见该文件」，不得在用例中写入任何账号或密码）。
- **沙箱买家账号**：由 Grace 发放，见 v0.2.2 附录第 1.2 节。

**常见问题/排查提示**：
- **Q：收不到验证码？** A：先查垃圾箱；stage 用独立 Supabase，邮件可能延迟；确认邮箱填写正确；仍收不到按 v0.2.2 反馈模板提交，注明邮箱服务商。
- **Q：沙箱付款报签名/验签失败？** A：核对后台填的是**支付宝公钥**而非应用公钥；两者容易混。详见 §4 的 C-26。
- **Q：stage 用 HTTP 会不会不安全？** A：stage 长期 HTTP、只放测试数据，不产生真实资金；支付跳转仍走支付宝沙箱 HTTPS 收银台。

**常见问题/排查提示**：
- **Q：折扣码输了没反应？** A：折扣码自动转大写；是否生效以「已使用」提示与金额明细为准。

| C-24 | 超时未付库存释放 | 已提交订单但未支付，超过支付截止时间 | 1. 等待超过支付截止时间（默认 30 分钟，可请 Grace 调低 `order_timeout_minutes` 加速）；2. 打开支付结果页或订单中心 | 支付结果页显示「订单已关闭或支付超时」「请重新选购并创建订单」；订单占用库存被释放 | §8-13 既有链路 | | 加速测试可请 Grace 临时调低超时分钟数 |
| C-25 | 支付页一直转圈 | 已点「去支付宝支付」 | 1. 确认浏览器允许本站弹窗与外部跳转；2. 仍失败按 v0.2.2 反馈模板提交，附 `outTradeNo` 与截图 | 正常应外跳支付宝；若卡在「正在创建安全支付」并报错，显示「无法发起支付」与原因 | | | |

**常见问题/排查提示**：
- **Q：沙箱已扣款但站点仍待支付？** A：先刷新结果页或进订单中心核对；结果页最多轮询 5 分钟，超时后停止；若长时间不更新，按模板反馈并附 `outTradeNo`（结果页有显示）与截图。
- **Q：会不会扣真实钱？** A：不会，沙箱与真实资金隔离。
- **Q：超时后库存何时释放？** A：由 cron 定时任务释放（配套《后台与系统侧用例》S-xx 覆盖）；支付截止时间一到，订单即标记为可释放。

## 5. 客户售后申请（v0.3.0 新增）

> **核心新增**：用户可按商品发起退款申请，经后台审核后退款。申请本身不动钱、不动库存。准入规则：普通原因仅 `queued`（待排产）可申请；尺寸不符 / 装配问题为例外，可在任何已进入打印流程的状态申请。详见 [CHANGES-v0.3.0 §3 D3/D5、§6、§7](./CHANGES-v0.3.0.md)。
>
> 售后入口在**订单详情页** `/account/orders/<订单号>`，无需单独的售后页面。

| 用例编号 | 场景 | 前置条件 | 操作步骤 | 预期结果 | 关联验收项/错误码 | 结果 | 备注 |
|---|---|---|---|---|---|---|---|
| C-27 | 普通原因发起申请（queued 商品） | 已支付订单，某商品打印状态为「待排产」（queued） | 1. 订单详情页 `/account/orders/<订单号>`；2. 在「商品与生产进度」区找到该商品，勾选「申请退款」；3. 选申请数量；4. 「提交售后申请」区选原因（如「质量问题」），填说明（1–500 字）；5. 可选上传凭证（≤5 张）；6. 点「提交申请」 | 提交成功，表单清空，页面刷新；「售后处理记录」区出现新申请，状态 `pending`；商品行显示「已退 0 件 · 可申请 N 件」 | §8-9 客户端准入 | | 申请仅记录诉求，不触发退款或返库 |

**常见问题/排查提示**：
- **Q：为什么有的商品不能勾选「申请退款」？** A：普通原因下只有 `queued`（待排产）可申请；若订单已有一条 `pending` 申请，该订单所有商品的可申请标记会关闭，需先撤销现有申请或等其处理完。
- **Q：尺寸不符和装配问题为什么能对已完成的商品申请？** A：外壳是精密配合件，这两类投诉率高于普通商品，作为例外情形允许后台在任何状态受理（D5）。
- **Q：申请提交后多久退款？** A：需后台审核通过后退款；本期无邮件通知，**审核结果请在订单中心查看**。
- **Q：凭证图片上传后在哪？** A：存于当前用户本站存储路径，数据库只保存对象路径；超过 24 小时未关联申请的孤儿文件由 cron 清理。

> 本期无邮件能力，审核结果只在站内订单中心可见（CHANGES §9 遗留风险）。申请状态：`pending` / `approved` / `rejected` / `completed` / `cancelled`。客户看到的审核说明为**固定文案**，后台原始说明只进审计日志。

**常见问题/排查提示**：
- **Q：部分退款后订单为什么没变成「退款中」？** A：部分退款保持订单原状态（`96126c5` 修复的语义），只有全部退完才变为「已退款」；这是 v0.3.0 的设计，不是缺陷。
- **Q：审核说明为什么都是固定文案？** A：客户看到的审核说明是固定安全文案；后台填的原始说明只进审计日志，不直接对客户展示。
- **Q：退款多久到账？** A：沙箱退款到账以支付宝沙箱查询 `refund_status=REFUND_SUCCESS` 为准（需等 ≥10 秒再查）；生产退款行为可能与沙箱不同。
- **Q：退款后库存会回来吗？** A：是否返还库存由后台运营在审核时逐件决定（`restock`），客户侧不可见也不可控；可售数量回升由系统自动处理。
