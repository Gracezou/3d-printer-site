# v0.2.3 验收记录

> 验收日期：2026-09-16
>
> 结论：**性能门禁未通过，暂停正式迁移与发布**

## 1. 结论摘要

上海服务器加固、跨境 L1/L2/L3 测量、低内存 stop-start 发布、健康失败自动回滚和库存并发正确性均已完成。上海应用到 Supabase 新加坡区的 L1 热连接 p95 为 68.06–76.31 ms，单次往返正常；但业务链路放大了多次跨境往返：

- 上海真实登录购物车 p95：884.99 ms；
- 上海完整“加购 → 试算 → 创建订单”p95：6295.60 ms；
- 上海创建订单阶段 p95：2972.97 ms；
- 上海“10 抢 5”总耗时：5842.20 ms，正确性仍为 5 成功、5 个 40901、无超卖。

创建订单 p95 超过需求规定的 2 秒强制改造线，因此未切换 DNS、正式域名或公网业务流量。新加坡继续承载现网，上海仅保留 loopback 预部署环境。

完整统计、跨境净增量和替代方案见 [`../ops/LATENCY-BASELINE.md`](../ops/LATENCY-BASELINE.md)。

## 4. 数据与安全

- L2 使用临时 Supabase Auth 用户和真实 session cookie；L3 使用隔离地址、购物车、商品、SKU、耗材和订单。
- 所有测试数据由 `finally` 路径定点删除；报告只保留脱敏聚合统计，不保留邮箱、手机号、UUID、连接串或 token。
- 两地并发扣料失败事务没有残留订单，成功订单数和耗材预占量一致。
- 仓库凭据扫描未发现服务器密码、SSH 私钥、数据库连接串或 Supabase Service Role 值。

## 5. 未执行与阻断项

以下工作不是遗漏，而是受 L3 门禁或外部条件阻断：

1. 正式 DNS 与公网流量迁移：L3 超过 2 秒，按需求必须暂停。
2. 域名、HTTPS、Supabase Auth 回调和构建地址切换：依赖迁移决策与备案输入。
3. ICP 展示及接入商核验：依赖备案结果。
4. 支付宝生产回调：依赖企业商户能力批复，且不属于本次性能测试。
5. `v0.2.3` Tag 与正式 Release Notes：性能门禁解除并完成人工公网回归后再执行。

## 6. 下一决策

在恢复迁移前需选择并实施其中一条路线：

- 短期优先：设计并验证单个下单存储过程，减少核心事务约 10 次跨境往返，同时优化购物车查询；
- 中长期：评估数据库迁入中国大陆及 Supabase Auth/RLS/Storage 依赖拆分。

改造完成后必须重跑 L2 五类接口、30 次完整下单和两地“10 抢 5”，不得只复用本次 L1 结论。
